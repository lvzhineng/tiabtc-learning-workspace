# 复盘优化与回归记录

记录日期：2026-10-02。环境：Windows、Python 3.14.2、Node 24.13.0、本机 Chrome。以下数据来自合成数据与模拟接口，不代表真实交易所网络耗时。

## 内存边界

| 数据 | 保留上限 | 淘汰方式 |
| --- | --- | --- |
| 活动图表 K 线 | 12,000 根 | 延展方向保留近端，未来预取优先保留回放游标附近 |
| Bybit 请求结果 / CFD 请求结果 | 各 48 批（已有边界） | 淘汰旧批次 |
| 交易 / 仓位行情窗口缓存 | 48 分片，每片最多 4,000 根（已有边界） | 分片 LRU，仓位带 candle venue |
| 时间书签 | 每种市场 100 个 | 新书签替换同坐标，超限淘汰最旧 |
| 性能记录 | 前后端各 200 条 | 内存环形记录 |

12,000 是活动图表对象数量的边界，不是整个浏览器进程的固定字节上限。图表库、画图、请求缓存和浏览器自身还有额外内存。淘汰不会修改 SQLite；保留的视口按毫秒时间映射回新的逻辑索引，保留小数偏移和缩放。若整个可视窗口已被淘汰，则保持缩放并夹到仍加载的边界；自由回放向前退一根时，会先重新加载淘汰的历史。

## 仓位读取与成交归属

GET `/api/position-review` 继续返回完整仓位摘要，兼容列表、标签、看板与绘图。查询只物化这些仓位对应 `(venue, chart_symbol)` 的起止范围内成交，复用已有 `idx_position_fills_symbol_time`，不创建表或索引。配置、仓位、成交、标签和余额在同一个只读事务中读取。

成交归属按 symbol 和时间排序，用活动区间集合与退出时间最小堆处理时间重叠的仓位。交易所过滤、2 秒匹配容差、严格区间优先、最近开仓优先与相同开仓时间的原顺序规则保持一致。大量同时重叠的仓位仍需要逐个判断，优化收益主要来自长历史中的非重叠仓位。

基准命令（只执行可信本地 Git 版本的算法，SQLite 使用 `:memory:`）：

```powershell
python scripts/benchmark_review.py --baseline-ref 9b7bd45c40358ebc72b06d8d71325e2484b31a95
```

| 合成场景 | 修改前中位数 | 修改后中位数 |
| --- | --- | --- |
| 3,000 个顺序仓位 / 6,000 笔成交归属，3 次 | 2,887.14 ms | 34.74 ms |
| 106,000 行成交表读取，相关成交 6,000 行，3 次 | 107.42 ms | 4.00 ms |

查询计划确认使用 `(venue, chart_symbol, time_ms)` 索引。基准同时核对顺序场景与 100 组固定种子的随机重叠场景，新旧算法输出完全一致。查询时间只测读取 / 物化，不包含完整 HTTP 响应序列化；接口仍返回全量仓位摘要，极大账户的响应体大小没有改成分页。

## 回归覆盖

后端已有测试文件增加范围读取与长历史候选数量回归，共 49 项通过。前端增加 7 项逻辑回归和 4 项浏览器回归：

- 累计 150,000 根的前后延展有界，重叠 K 线修订保留，视口小数偏移不变。
- 真实图表与数据 hook 连续预取 60 次；活动数据有界，未来 OHLC 隐藏，保留的定位不跳动，淘汰边界回退能补回历史。
- 首屏 ArrowRight 进入自由回放，书签刷新恢复，CFD 与永续偏好隔离，CFD 不显示成交量 / 模拟交易、不发模拟交易请求。
- 待复盘过滤与刷新记忆，bit浪浪画线跨周期保留 / 跨交易隔离，导出包含已保存笔记、原始备注与 PNG，文本转义。
- 五个入口与默认顺序学习、亮暗主题、仓位待复盘 / 卡片、设置性能表可用，展开密钥面板时列表仍可点击。
- 相邻时段归属排除持仓 / 未来样本，性能记录数量有界且快照可独立修改。

浏览器长回放会在请求缓存充分预热后和最后采样强制 GC 后的 JS 堆，并输出 `replay-performance.json`。它用于跟踪趋势，不对跨机器的绝对毫秒数或堆字节数设置脆弱断言；测试的硬约束是活动 K 线数量、视口时间和回放行为。

本次 60 次预取结果：活动数据始终最多 12,000 根；第 48 次延展后的 JS 堆为 20,622,204 字节，第 60 次后为 20,686,956 字节，增加 64,752 字节（约 63 KiB / 0.31%）。整个延展过程约 13.4 秒，其中包括浏览器点击、等待视口稳定与 GC。该采样不是浏览器 RSS 或实盘网络压力测试。

## 结构与人工检查

独立的 `position_review_reader.py` 负责只读仓位组装；`review-ui-state.ts` 负责行情工作台偏好校验；`useChartExport.ts` 复用两套交易图表的截图 / 卡片导出。HTTP 路由、同步、画图持久化与界面编排继续沿用现有入口，逐步减少大型文件职责。

自动化使用夹具与临时库，不验证真实交易所鉴权、网络限频、用户历史画线或生产数据。人工可在现有服务上抽查：长时间左右拖动和回放、1m / 1h 切换所选交易居中、保存笔记 / 标签后待复盘列表变化、真实画线刷新恢复、复制图片、CFD 休市跨越与非 BTC/ETH 所属交易所行情来源。本次没有修改数据库结构或生产数据。
